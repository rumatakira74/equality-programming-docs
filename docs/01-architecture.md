# 1. Архитектура

Полный источник: спецификация основного репозитория — `docs/KNOWLEDGE.md` (оглавление; содержимое — в частях `docs/KNOWLEDGE-1..5.md`), разделы 3, 9, 12 (части 1 и 4). Здесь — практический конспект текущей реализации.

## Слои приложения

```
Flutter/Dart (UI)
   │  platform channels
Kotlin: NodeService (foreground service), Keystore, биометрия, PIN
   │  вызовы AAR (gomobile bind)
Go-ядро: core · cons · net · mobile · sim · cmd
```

- **Flutter/Dart** — весь интерфейс участника: онбординг, кошелёк, реестр, поручительства, миграция, смена гардианов, режим-приманка.
- **Kotlin** — платформенный слой: Android Keystore (ключи кошелька), биометрия, PIN (PinManager), foreground service (NodeService). Ключи не покидают Keystore: ядро проверяет подписи, но ими не владеет.
- **Go-ядро** — сетевой стек (go-libp2p: QUIC/TCP, Noise, DHT Kademlia, GossipSub, hole punching, circuit relay), проверка транзакций и аттестационных цепочек, PoW, консенсус, чекпоинты, хранилище.
- **Связка:** `gomobile bind` → AAR; обмен сообщениями через protobuf; замер моста — 5–22 мкс на вызов.

## Потоки (критично для Android)

- **Весь cgo — off-main.** Блокирующий `startNode` на главном потоке давал ANR (bootstrap до ~11 с) — релиз-блокер, исправлен: `onStartCommand` уходит в фон, готовность приходит колбэком. Все вызовы моста проверяются на блокировку UI.
- Мост Kotlin потокобезопасен: `mainHandler` / `executor` / `ConcurrentHashMap` (аудит этапа 9 — находок нет).
- Read-слой UI к реестру — `net/query.go` (геттеры под `sync.RWMutex`; `Apply` держит Lock). Прямые чтения внутренних структур ядра из UI запрещены (data race — этап 7, авторизованное исключение).
- UI **не дублирует** формулы протокола: экран выпуска берёт `claim_period`/`claim_amount` у узла, окно челленджа — через `CheckMintChallengeWindow` (да/нет). Точная логика — в Go.

## Хранение

- **SQLite** (продакшен-режим) — цепочки, индексы, кэш пиров.
- **In-memory** — режим песочницы/эмуляторов (находка №38: SQLite в песочнице падал SIGSYS; на живом телефоне — SQLite).
- **allowBackup=false** — резервное копирование БД отключено (защита от случайной эквивокации при откате `seq`).
- Снапшоты — state commitments: корень sparse Merkle-дерева состояния в чекпоинте.
- Лёгкий узел хранит свою цепочку, свои входящие и заголовки чекпоинтов; баланс проверяет Merkle-доказательством.

## Уровни узлов

| Уровень | Поведение | Режим |
|---------|-----------|-------|
| Полный | Хранит и проверяет весь реестр, ретранслирует, голосует | Зарядка + Wi-Fi, foreground service |
| Лёгкий | Свои данные + заголовки чекпоинтов, Merkle-доказательства | Обычный режим телефона |

За мобильным NAT (CGNAT) входящих нет — hole punching и ретрансляция через добровольные полные узлы (libp2p circuit relay). Это не серверы проекта, но и не «чистый P2P» — фиксируется честно.

## Криптография

- **Подписи кошелька:** ECDSA P-256 (Keystore надёжно поддерживает; Ed25519 — не везде). Подтверждено на целевых устройствах.
- **Каноничность:** строгий DER + low-s во **всех** путях подписи (этап 9: мalleабельность ECDSA — TxID включает подпись — давала ложные конфликты; исправлено, регресс-тесты есть).
- **Аттестация:** разбор KeyMint/Keymaster через `encoding/asn1`, проверка цепочки локально каждым узлом по корневым сертификатам Google, зашитым в APK. Проверяются hardware level, `verifiedBootState=Verified`, `deviceLocked`, уровень патча. Play Integrity и серверы Google не используются.
- **PoW:** лёгкий SHA-256 (таргет 2^24, ~1–4 с) на `transfer`; memory-hard Argon2id 32 МиБ (таргет 2^56, ~10–20 с) на `register` и выпуск.
- `walletFingerprint = SHA256(attestedPublicKey ‖ protocolId)`; один фингерпринт — один адрес.

## Безопасность UI (правила этапа 9, спека 8.2)

- Вход — отпечаток или PIN.
- Все деструктивные операции (перевод, в т.ч. BT-путь; выпуск; миграция propose; смена гардианов (публикация/отмена); смена/удаление PIN) — **только явный ввод PIN**. Биометрия после PIN — только «разблокировка ключа».
- Каждый PIN-промпт — точка входа в режим-приманку (обычный или тревожный PIN); биометрическое подтверждение перевода запрещено полностью.
- При активном тревожном PIN вход по отпечатку отключён.
