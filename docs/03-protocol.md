# 3. Конспект протокола

Короткая выжимка правил, которые реализованы в ядре. Полный текст и обоснования — спецификация основного репозитория: `docs/KNOWLEDGE.md` (оглавление; содержимое — в частях `docs/KNOWLEDGE-1..5.md`), разделы 4–13, 17 (части 2–5); параметры — раздел 17 (часть 5) и genesis-прото.

## Транзакции и реестр

- Типы ядра: `register`, `vouch`, `mint`, `transfer`, `migrate`, `evidence`, `guardian_offer`; модульные: `pool_*`, `redeem`/`receipt`, `contribution_*`.
- У каждого кошелька **своя цепочка**: `{wallet, seq (+1), prev, type, payload, timestamp_claim, подпись}`. Двойная трата = два подписанных продолжения одного звена — тривиально доказывается.
- Баланс = сумма валидной истории; каждый узел пересчитывает сам.
- Заявленный timestamp допускается при расхождении с сетевым временем не более ±30 мин.

## Время

- Сетевое время — от финализированных чекпоинтов, не от медианы timestamps. Календарь UTC; периоды сети — **календарные от genesis** (№39: слот челленджа привязан к genesis-времени; окно ±48 ч).

## Консенсус

- Конфликты разрешаются выборочным голосованием **Snowball** (Avalanche-подобно): k=10, α=0.7, β=4; веса опрашиваемых — по возрасту и аттестации кошельков. Ответ голосования подписан (wallet + ECDSA).
- **Чекпоинты:** эпоха 24 ч; пороговая подпись N=14 из M=21 валидаторов эпохи; хеш — корень sparse Merkle-дерева состояния (балансы + seq); `checkpoint_hash` не включает подписи (детерминизм). Режимы: `decentralized`, `members_quorum` (малые сети, до ~100 участников; чекпоинт O(N)), переходный `seed`-режим посевного круга.
- `seed_sunset`: посевной круг теряет особые права при 100 `active`-кошельках **или** 24 эпохах.
- Решение №42 (этап 9, утверждено (A)+(D)): очередь строителей чекпоинта из первых K по составу с ротацией; застрявшая (пустая) эпоха пропускается — определение «пустой эпохи» фиксируется в спеке v9.6.
- **Сверка журнала:** `SyncJournalFrom` — позиционный якорь (№41): позиция в нумерации журнала пира + txid на границе, per-peer продолжение, выравнивание при расхождении. Рестарт из БД: `ImportJournal` / флаг `-import-db` — импорт tx с пинированием часов на `timestamp_claim` (№40: `cons.Replay` пинирует только NetTime → демередж из БД расходился с холодной сверкой; регресс-тесты закреплены).

## Вход, идентичность, анти-ферма

- `register`: аппаратная аттестация + memory-hard PoW. Один фингерпринт — один адрес.
- Активация: K=3 `vouch` от разных `active`-кошельков (возраст поручителя ≥3 мес., слоты 3/5/10, посевной круг — 10 на первый год). Награда поручителям R=10% от первых 12 выпусков поручаемого (из его выпуска, не из эмиссии).
- Выпуск: периодический равный (по умолчанию 1000/мес.), только `active`, только завершённые периоды (первый выпуск — в периоде после активации), челлендж в непредсказуемом слоте (`H(address ‖ period ‖ hash(чекпоинта предыдущей эпохи))`), окно накопления 6 мес.
- Мораторий `transfer`: 7–30 дней после `register`.
- Эквивокация → `evidence` от любого узла → метка `flagged`, приостановка выпуска 3 мес. (повтор — навсегда), запрет vouch от `flagged`. Денежных штрафов и залогов нет.
- Отозванные аттестационные сертификаты: механизм отзыва (№43) отложен для v1; сейчас проверяется только уровень патча (не просрочен, «будущая дата патча» — минор-фикс в этапе 10).

## Экономика

- Комиссия перевода **сжигается**: `fee = max(fee_min, rate × amount)`, `fee_min = 0,01`, rate ∈ [0,5; 2]% адаптивно (детерминированный пересчёт на границе эпохи из данных чекпоинтов; все узлы получают одно значение).
- Демередж: 1% сверх floor 3000, детерминированный пересчёт по числу прошедших эпох; списанное сжигается. Обязателен для профилей с передаваемой ценностью.
- Отложенные переводы: порог P=3000, максимум P_max=30000, задержка D=48 ч фиксированная, отмена подписью владельца в течение задержки.

## Сеть

- Bootstrap-каскад: кэш пиров (SQLite) → подписанные seed-списки (Telegram-каналы, best-effort) → зашитый в APK список → NSD/mDNS → Bluetooth-скан → QR → ручной ввод; затем DHT + gossip. Защита от eclipse: смешивание источников, несвязанность пиров по подсетям /24 и /64 (№35; ASN — PENDING), подтверждение от N несвязанных пиров.
- `network_id` различает инстансы; в `invite_only` — адреса первых узлов и ключ сети в приглашении.
- Bluetooth: только передача подписанной tx получателю; оплатой она становится после публикации и подтверждения сетью.
- Локальные флоты (localhost, одна /24): запускать с `-link-groups=false`, иначе классификатор связанных подсетей сочтёт все узлы одной группой и заблокирует corroboration. В продакшене дефолт включён.

## Управление

- Ролей управления нет. `params_mutable=false` по умолчанию; при `true` — только в границах `mutable_bounds` из genesis, порог ≥2/3 `active`, задержка ≥30 дней, неретроактивно. Защитные параметры (K, D=48 ч, `transfer_mode`, эмиссия, `device_policy`, `signing_auth`, `checkpoint_mode`, `params_mutable`) не меняются никогда.
- Право форка: любой участник продолжает сеть на прежних правилах с той же историей (форк-пакет из чекпоинта).
- `protocolVersion` в каждой транзакции и чекпоинте; релизы APK и seed-списки — мультиподпись N-из-M.
