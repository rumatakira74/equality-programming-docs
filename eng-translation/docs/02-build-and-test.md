# 2. Build and tests

## Toolchain

| Component | Version/tool |
|-----------|--------------|
| Core | Go, `gomobile bind` → AAR (Go 1.27: the `-checklinkname=0` flag — anet linkname directives) |
| Android build | Gradle 8.11.1, AGP 8.9.1 (CI aligned to it at stage 9) |
| UI | Flutter/Dart, Kotlin platform layer |
| App build | Release: R8 + production signing (topic A8/fix-release-keys: the signing config is generated by configure — `TNP_SIGNING_PROPERTIES`, `TNP_KEY_KIND=std\|rec`, verification of the `TNP_SIGNING_KEY_SHA256` fingerprint and file permissions ≤0600 by the verifySigning task; a release without the production key is rejected — see docs/RELEASE-KEYS.md in the main repository); name `equality-{global|slug}-{std|rec}-v{version}.apk`, applicationId `io.equality.<sanitized-slug>.x<hash8>` (global — `io.equality.global.x<hash8>`), label `Eq-<hash8>` |
| Emulators | AVD x86_64 + KVM (arm64 crashed in NDK translation — use x86_64) |

## Core verification commands

- `go test ./...` — the full suite; must be green.
- `go test -race ./core/... ./cons/... ./mobile/... ./net/...` — races; stage 9 closed three high ones (Snowball, cons.Clock, cheapCheck/StateRoot); currently clean.
- Race is mandatory for `net/query` after any changes to the read layer.

## App checks

- `flutter analyze` — clean.
- `flutter test` — widget tests (including delayed transfers and the stage 9 PIN rules).
- Instrumented tests on the emulator (API 36, KVM): attestation, Keystore, biometrics — 5/5 at stage 6.
- Decoy/duress-PIN tests: lockout, the decoy, return to the real wallet.

## CI

- `android.yml` — Android build (AGP 8.9.1, gomobile bind `-checklinkname=0`).
- `cons.yml` — consensus.
- `core.yml` — `go test -race ./core/...`.
- `net.yml` — `go test ./net/...` + `go vet ./cmd/...`.
- `flutter.yml` — `flutter analyze`/`flutter test` + APK build (Flutter 3.47.9).
- CI does not run the emulator suites — they are executed manually per the runbooks.

## Known flake

`TestSideChannelPublishPropagates` (net) — a 30 s timeout while an emulator is running (CPU load from swiftshader). On clean runs without an emulator — green. If it fails, rerun without an emulator; do not count it as a regression without a rerun. A similar timing factor under load in `TestSyncAnchorContinuation` (net) — an 8-live backlog; green in a solo run.

## Test network and simulations

- `cmd/tnp-testnet` — generation of the genesis package, the manifest, seed lists, invitations (invite_only), and tx drivers; "fleet" mode — 48 persistent nodes on one host.
- `cmd/tnp-node` — a headless node (~12 MB RSS; 48 nodes <1 GB).
- Epochs for tests are accelerated via the `epoch_seconds` parameter (production — 24 h); PoW targets in tests are lowered.
- Emulator clock shift: `adb shell cmd alarm set-time`. Host clock shifts for long fleets — a controlled operation with timesyncd stopped and a **mandatory restore** (see [Process](04-development.md)).
- Memory for a full run: 2 emulators (~3.8 GB each) + the node fleet + CLI ≈ 10–13 GB RAM; if short, cut headless nodes, not emulators. Stop Gradle daemons before a run.
- Runbooks and results — `reports/` of the main repository (`reports/stage8/TESTNET-RUNBOOK.md`, stage reports, artifacts of 50-node runs).
